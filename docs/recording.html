Voice & video

Capture the explanation beside the page.

Record a spoken thought or a screen walkthrough and keep it as an ordinary attachment in your local vault.

Record a voice note Record the screen

Start from the page.

  1. Open a page in a writable local vault.
  2. Choose the microphone or video-record icon beside Print, or in Attachments.
  3. Record, review, and save to that page.

The recorder displays a destination such as Projects:Demo. It stays bound to that page if you navigate elsewhere.

Voice notes

Speak now. Keep the context.

Click the microphone, or choose Record Voice Note in the command palette. The Attachments panel opens alongside the recorder. Opening it does not start microphone capture.

  1. Select a microphone and press Record. Watch the input-level meter while speaking.
  2. Pause and resume as needed, then Stop. Press Play to review.
  3. Choose M4A for compact audio when AAC encoding is available, or WAV for uncompressed audio.
  4. Press Save to attach the recording to the original page.

Double-click an audio attachment for playback with seeking and volume controls. If saving fails, the draft is retained for retry. Discarding captured audio requires confirmation.

Optional transcription

Choose a transcription server and speech-to-text model in Preferences → Audio, then open an audio attachment and press Transcribe. This sends the recording to your configured server. Copy the resulting text or save a transcript. Recording and playback do not require transcription.

Screen recording

Show the steps, with optional narration.

  1. Click the video-record icon, or choose Record Screen in the command palette.
  2. Select a display and preview it. On Wayland, Choose screen opens the desktop screen-sharing picker.
  3. Leave Microphone Off for silent video, or select a microphone for narration. System audio is not recorded.
  4. Press Record and approve any desktop shortcut prompt. A large animated 3 → 2 → 1 countdown precedes recording.
  5. The window shrinks into a movable recording bar. Its timer and pulsing red indicator show recording; steady amber means paused.
  6. Stop, review the video, and press Save attachment. Stopping does not automatically save the attachment.

The bar starts at the bottom center of the selected display and remembers where you drag it. MP4 is preferred; available encoders determine the actual format, with fallback when an encoder fails before recording any media. Save failures retain the draft and show its location.

Double-click a video attachment to play it inside StillPoint.

Stay in control

Use the tray. Keep the bar optional.

Steady recording status

The system tray/menu-bar icon is red while recording and amber while paused. Its recording menu shows elapsed time and offers Pause/Resume and Stop and review.

Hide the floating controls

Turn off Show recording bar in the tray menu. That preference is remembered. A temporary recording tray icon is provided when the normal icon is disabled; without a usable tray, the bar remains available.

Review after capture ends

Stop and review ends capture before opening playback. Whole-screen capture can include the floating bar, OS panel, and open tray menus. Hide the bar and use a global stop shortcut to avoid opening a menu in the video.

Global shortcuts

Start, pause, or stop while another app has focus.

Start on the current page

Windows and Linux: Ctrl+Alt+Shift+R

macOS: Control+Option+Shift+R

Pause / resume

Windows and Linux: Ctrl+Alt+Shift+P

macOS: Control+Option+Shift+P

Stop and review

Windows and Linux: Ctrl+Alt+Shift+S

macOS: Control+Option+Shift+S

Start stays registered while StillPoint is running. Pause and stop are registered for an active screen recording and released when it ends. These bindings do not control voice notes. On macOS, Control is the physical Control key, not Command; R, P, and S refer to ANSI key positions.

Start targets the current writable local page in the most recently focused StillPoint window and reuses your last screen and microphone choices. The countdown and permission checks still apply. Missing saved devices require a replacement, and active recordings or unsaved reviews are preserved. Wayland still opens the system screen picker.

Wayland uses the desktop Global Shortcuts portal, which may ask you to approve or choose bindings. The tray menu reports the actual granted bindings. Conflicting shortcuts, denied permissions, and unsupported desktops are reported; the bar and tray remain available.

Platforms & permissions

Local files, native desktop capabilities.

  • Screen recording uses Qt Multimedia's FFmpeg backend. Source installs need PySide6 6.8 or newer and the project's requirements.
  • On newer Wayland desktops, global-shortcut permission requires an installed application identity. The Linux installer supplies a hidden app.stillpoint.StillPoint.desktop entry; rerun it after updating a packaged build.
  • Windows and macOS use native global-hotkey APIs. Linux X11 uses key grabs; Wayland uses the Global Shortcuts portal.
  • Qt's Wayland screen capture is experimental and requires PipeWire and a compatible screen-sharing portal. Global shortcuts additionally need a desktop portal backend implementing Global Shortcuts.
  • On macOS, grant screen-recording permission in System Settings → Privacy & Security. Voice notes and narration also need microphone permission. Source development should use venv/bin/python tools/run-macos-dev.py.
  • If capture, an encoder, or saving fails, read the recorder's message and preserve the draft before discarding it. Screen recording supports local vaults.
